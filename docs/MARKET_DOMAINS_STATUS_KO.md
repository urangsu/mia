# 금리·자료 분류 구현 상태 (2026-10-30)

## 구현 및 로컬 검증

- 기존 SQLite 원천 테이블은 그대로 유지한다. 수집 후 domain_market,
  domain_metal, domain_stock View를 갱신한다. 각 행에 원천 테이블명·종목·기준일·
  전체 원자료 JSON을 남긴다. DB 파일을 세 개로 분리하지 않는다.
- prior_estimates는 관측 테이블과 별개다. 현재 값과 동일 기준의 변화량,
  명시적 현재/이전 날짜, 단위, 출처, 기준 확인이 필요하다. 계산 종류는 pct,
  absolute, bp다. 반올림 수치로 얻은 결과는 derived_estimated이며 확정 종가가 아니다.
- HTML에 미국 10년·한국 10년·한국 3년·회사채 3년 AA− 카드가 있다.
  금리 수준은 소수점 셋째 자리 %, 변화는 소수점 첫째 자리 bp다.
  자료가 없거나 최신 행이 모호하면 —로 표시한다. 실제 날짜는 원자료에 유지한다.
- 신규 4개 포함 총 459개 테스트 통과 (macOS, Qt offscreen).

## 아직 완료되지 않은 부분

- 한국 3년/회사채 원천 수집과 실제 브라우저 대조. Computer Use가 Work 설정에서
  비활성화되어 검증하지 못했다. 확인되지 않은 종목 URL이나 값을 넣지 않았다.
- 역산은 명시적 입력을 받는 저장 함수까지만 구현했다. 비교 기준이 확인되지 않은
  사이트 데이터를 자동 역산하거나 확정 보고서에 자동 편입하지 않는다.
- 사진 전체 카드/차트 재배치, KOSPI 수급 수집, DXY 수집, API 요약 연결은 미완료다.
- 회사 Windows/SQLite 운영본/ECM 검증은 미수행이다. 배포 여부와 실제 회사 인수는 별개다.

예: `SELECT * FROM domain_metal ORDER BY observation_date DESC;`
기존 DB는 다음 수집의 CSV 단계에서 View를 만든다. 단순 앱 실행만으로 기존
운영 DB를 변환하지 않는다. 실제 데이터 파일을 공개 Git에 넣지 않는다.
