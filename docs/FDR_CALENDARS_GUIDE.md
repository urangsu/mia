# 공개 종가 · 거래일 캘린더 운영 안내

## 설치와 실행

Python 3.10+가 필요합니다. Windows에서는 기존 폴더를 보존한 개발 사본에서 시작하세요.

```text
py -m pip install -r requirements-desktop.txt
py FastmarketsCollector_v3_7.py
```

설정 화면에서 FDR 공개 종가, 관심종목 6자리 코드(쉼표 구분, 최대 25개), 종목당 제한시간(1~120초)을 지정합니다. 기본 관심종목은 POSCO홀딩스 `005490`, 제한시간은 20초입니다. 앞자리 0을 보존하세요. FDR는 일반 설정 로드 시 기본 활성화하며 기존 Fastmarkets·SMBS·NAVER DOM 토글은 별도로 유지합니다. 화면의 새 `주가 종가` 표는 시총 순위 표와 다릅니다.

브라우저 연결 없이 독립 확인할 명령입니다. 저장 폴더와 Excel은 운영 원본 대신 테스트 사본 경로로 지정하세요.

```text
py FastmarketsCollector_v3_7.py --once --public-only --data-dir C:\mia-test\data --workbook C:\mia-test\public.xlsx --report-dir C:\mia-test\reports
```

`--public-only`는 FMB/FX/NAVER DOM을 끄고 FDR만 켭니다. ChromeSession을 생성하지 않습니다. `--fdr-force`는 당일 성공 캐시를 우회해 원천 정정을 재확인하고, `--no-fdr`는 기존 수집만 실행합니다. `--reports-only`는 재수집 없이 저장된 DB로 보고서를 다시 만듭니다. 다른 날짜에 다시 생성하면 그 생성 시점의 기대 거래일을 검사하므로 과거 가격을 오늘 종가로 확정하지 않습니다.

종료 코드 0은 전체 완료, 2는 부분 성공/실패입니다. 현재 KR10Y가 미지원이므로 공개 전용 실행도 보통 partial/2를 반환합니다. 오류가 있어도 정상 종목의 원본과 보고서는 보존됩니다. 로그와 실행 진단의 종목별 상태를 확인하세요. 이를 스케줄 실패와 혼동해 전체 데이터를 삭제하지 마세요.

## 무엇을 수집하나

| 보고서 코드 | FDR 원천 | 단위 | 거래일 기준 |
|---|---|---|---|
| KOSPI/KOSDAQ | NAVER:KOSPI / NAVER:KOSDAQ | points | XKRX |
| SP500/NASDAQ | YAHOO:^GSPC / YAHOO:^IXIC | points | XNYS / XNAS |
| US10Y | YAHOO:^TNX (CBOE 지수) | % | XNYS |
| GOLD/WTI | YAHOO:GC=F / YAHOO:CL=F (연속선물) | USD/troy oz / USD/bbl | CMES |
| 관심종목 | NAVER:6자리 코드 | KRW/share | XKRX |

NAVER 이력은 기존 화면의 DOM을 읽는 대신 FDR 공개 HTTP 경로로 가져옵니다. 실제 원천 URL·심볼·수집 시각·시장일·Close·단위·캘린더 버전을 원본과 보고서에 남깁니다. KRX 인증 경로는 사용하지 않습니다. 실제 조회에서 Yahoo 한국 지수 최신값 누락을 확인해 한국 지수에는 NAVER를 선택했습니다.

KR10Y의 검증된 일별 경로와 시총 Top10은 이번 통합에서 제공하지 않습니다. 월별 금리를 일별로 늘리거나 종가로 시총 순위를 꾸미지 않습니다. ^TNX는 미국 재무부 공식 고시가 아니며, 연속선물 Close는 금 현물/실물 WTI/공식 정산가와 다릅니다. 전용 거래소 공시 달력과 공급자 게시 시각을 완전히 보장하지 않으므로 회사 보고서 채택 전 원문 대조가 필요합니다.

## 오전 실행의 날짜 규칙

- 한국 수집일 당일 값은 종가로 사용하지 않습니다.
- 해당 시장의 실제 종료 시각과 20분 게시 유예를 지난 세션만 사용합니다. 휴일·DST·조기 종료는 캘린더를 따릅니다.
- 가장 최근의 종료 세션과 그 직전 종료 세션이 비교 대상입니다. 필요한 날의 Close가 비어 있으면 `missing_history`로 남깁니다. 더 오래된 두 가격으로 대체하거나 변동률로 역산하지 않습니다.
- 캘린더는 가격 출판/품질 증명 도구가 아닙니다. 특히 선물은 CMES 세션을 보수적 기준으로 사용하며 실제 공급자 심볼의 게시 지연과 결측은 별도 감시해야 합니다.

## 누적·정정·출력 계약

별도 SQLite 테이블 `fdr_observations`, `fdr_targets`, `fdr_price_revisions`, `fdr_quarantine`을 추가하며 기존 FMB/NAVER 원본을 덮어쓰지 않습니다. 원본 가격은 Decimal 문자열로 보존합니다. 동일 수치 재실행은 가격 정정 이력을 늘리지 않습니다. 성공한 종목의 당일 기대 두 종가가 이미 있으면 HTTP를 생략합니다. 미완료 종목은 다시 시도합니다.

같은 날 서로 다른 가격이 응답하면 이전 원본은 보존하고 해당 날짜를 보류합니다. 보고서와 프로그램 관리 Excel의 기존 값은 비우며, 이후 명확한 응답에서 같은 열에 복구합니다. CSV에는 보류 플래그, Excel에는 `FDR_종가원본`·`FDR_보류이력`이 있어 보고서에서 제외된 원인을 추적할 수 있습니다.

출력은 누적 Excel, 원자적 `public_closes.csv`, 같은 ReportContext의 HTML·편집 가능한 표 PPTX·context JSON입니다. FDR 가격열 키는 `FDR|종목|단위|Actual|MID`이며 NAVER DOM 키와 혼합하지 않습니다. 보고용 주가는 `보고용_주가` 시트에 있습니다. 동일 CSV는 다시 쓰지 않습니다. 출력이 실패해도 원본 DB를 지우거나 재수집할 필요는 없습니다.

취소/제한시간에는 이 프로그램이 생성한 HTTP 자식만 회수합니다. 기존 Chrome 9222/9444·일반/관리자 Edge 9337·프로필·토큰을 건드리지 않습니다.

## Windows 최소 인수 절차

1. 운영 DB/Excel을 사본으로 준비하고 위 공개 전용 명령을 실행합니다. 실제 원문 두 거래일·가격·단위를 6개 대표 지표/관심종목과 대조합니다. 금/WTI 결측을 수동 확인합니다.
2. 같은 날 재실행해 정상 종목은 캐시되고 정정 이력/동일 CSV 쓰기가 늘지 않는지 확인합니다. `--fdr-force`로 재확인해 정정과 보류 이력을 확인합니다.
3. 새 `주가 종가` 화면·관심종목 저장/재시작·취소·오프라인 오류를 확인합니다. 과거 NAVER DOM·FMB 수집과 사용자 Excel 수식/시트 보존도 따로 확인합니다.
4. Excel·HTML·PPTX의 기준일·값·출처·누락이 같은지 확인합니다. PPTX 표를 직접 편집해 봅니다.
5. 설정 저장 후 기존 `--schedule 08:30`, `--schedule-status`로 로그인한 Windows 사용자 작업을 등록/조회합니다. 예약은 저장된 출처 설정을 사용합니다. 수면/로그오프/회사 정책·08:30 실제 기동은 회사 PC에서 검증해야 합니다. ECM 서버 체크인은 별도 확인하며 자동 승인하지 않습니다.

실제 스케줄 등록과 회사 파일 쓰기는 이 개발 환경에서 수행하지 않았습니다.
